# Serein v1 — Scope & Status

**Date:** 2026-07-03
**Status:** Agreed scope (founder + eng)
**Parent:** [Product Roadmap](2026-07-02-product-roadmap-design.md)

The definitive "what v1 is" sheet. If it is not on this page, it is not in the
first public release.

## The one-line bet

> **The todo app that doesn't guilt you.** No account. No cloud. No streaks.
> Your tasks never leave your phone.

**Ship target:** lean mobile v1 on the App Store + Play Store in ~1 month.
**Model:** free forever core. (Pro unlock is v1.5; sync/sharing subscription is
v2.) No ads, ever.

## What "v1" deliberately is NOT

Cutting scope is the product. Explicitly out of v1:

- **No sign-in / accounts** (contradicts "no account"; only arrives with v2 sync).
- **No sync, no web app** — deferred to v2 (one merged project with tap-to-share).
- **No widgets** — v1.5 Pro (first native-code / dev-client investment).
- **No tap-to-share / Bluetooth** — v2. Bluetooth dropped entirely.
- **No calendar integration, tags, priorities, sub-tasks, AI** — Todoist-ward
  drift. "Scheduling" here means reminders + recurring, nothing more.

## Already built (in the working tree)

- Per-tab task store (Today / Upcoming / Someday) with AsyncStorage persistence.
- Gentle daily **rollover**: unfinished Today tasks carry over tagged "Undone";
  tapping the tag promotes to Upcoming.
- **Row gesture language:** tap checkbox = complete, tap text = edit inline,
  swipe left = delete. (Swipe-to-move was cut for calm/simplicity.)
- **Add-task UX:** visible commit button, light haptic, row enter-animation,
  stays open for rapid entry.
- **Notes tab:** day-grouped journal (Today / Yesterday / dates), write / edit /
  delete, virtualized with FlashList. (Keep / set-in-motion were cut.)
- **Tab bar** floating blur + rise-on-launch entrance.
- Health: **react-doctor 100/100**, **56 tests passing**, TypeScript + lint clean.

## Infrastructure decisions (all free-tier, Expo-Go-friendly for dev)

- **Sanity CMS (free)** — read-only app content/config only, never user todos.
  One `appConfig` doc (`minSupportedVersion`, `latestVersion`, `updateMessage`,
  `announcement`) + `devNotes` / `pipeline`. Cached CDN fetch on launch; app
  ships fallback content and never blocks/hangs when offline.
- **Force-update / nudge / announcement** — pure JS: compare running version
  (`expo-application`) to Sanity config. No native module. NOT a Sentry job.
- **Sentry (free Developer plan)** — crash/error reporting in EAS/production
  builds; daily dev stays in Expo Go. Chosen over Firebase Crashlytics (no
  mandatory dev client, no Google dependency, no redundant Remote Config).

## Brand

- **Sage "S"** — app icon (light + dark ready).
- **Green flame** — the **Pro mark**: the cue wherever a Pro feature is gated,
  and the alternate Pro app icon.

## Build order (smallest risk first)

1. Icons + splash wiring (config, no brainstorm).
2. Sanity content layer (light brainstorm — first runtime network dependency,
   built defensively).
3. Notifications + evening wind-down (full brainstorm — signature feature).
4. Recurring → export → onboarding.
5. Production machinery (wire Sentry at the first EAS build).

## Definition of done for v1

- All eight checklist items complete; icons/splash live in builds.
- Tests green, react-doctor healthy, clean run on a real iOS + Android device.
- Privacy policy published; store listings + screenshots submitted.
- First-run experience is calm and account-free end to end.

## First success signals (post-launch)

- Live on both stores within ~1 month of starting the remaining work.
- First 50 organic reviews mention "calm," "simple," or "no account."
- The v2 sync/sharing subscription is designed only after real users ask for it.
